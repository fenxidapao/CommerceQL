一、为什么要按"第几轮"分组
-----------------------------
W4 的离线复现把机制钉成**跨 run 的线程态累积**（入口残留 35 个通道，去掉组 1 身份 = 28 个 run 级；
`thread_id = {tenant}:{user}:{session}`）。这条机制有一个**免费的活体推论**：
> 如果成因真是"上一轮的通道残留"，那么**没有前一轮的第一次请求不可能中招**。
⇒ 把 A 档那 108 条按"该 user 的第几轮"分组，就是单变量对照：**首轮 vs 第 2 轮及以后**。
（几何支持这个分组：`driver.py` 同基取模 ⇒ worker `i` 固定用 `tokens[i%12]` 与 `session_pool[i%12]`
 ⇒ **一个 user 的一串请求 = 一个 thread 的连续几轮**，无需额外假设。）

-----------------------------

  复用臂两个都 True / 正常臂两个都 False / 崩臂 `零 stage` True 且 digest False）。跑法见文末。
