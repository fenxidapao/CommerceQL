## §3 提交与 git 纪律（违反其中任何一条，本项目历史上都出过事故）

- **显式路径 `git add`**；**禁 `git add -A`／`git add .`**（会把 `deploy/.env`、密钥、scratch、他窗在途件一起吞进去）。
- **禁 `git reset --hard`／`git checkout --`／`git clean`** 去"清理盘面"——盘上可能有他窗未提交的工作（§5 已经给了实例）。要留回滚点就**改名／stash 之外**的手段，且**禁 `git stash`**（共享工作区里会咬错人）。
- **禁 `--no-verify`／`--no-gpg-sign`**。钩子红了就查根因；钩子红 ⇒ 提交**没有发生**，此时若去 `--amend` 会毁掉上一件的已提交内容。
- 一次提交一件事；commit message 用 `type(scope): 结论 —— 关键读数` 形状（照 `git log` 现有风格）。
- 提交前**同节数字两两对撞**（我这边栽过一次：`117+8+5+35` 写成 160，实为 165）。
- 中文 Windows 的 EOL 坑：`.gitattributes` 是 `* text=auto eol=lf` ⇒ **新克隆是 LF、本机工作副本可能 CRLF 并存**；改大文档前**先探 EOL 再落笔**，别断言。工具新建的文件**落盘立刻现算 CR 数与 md5**（别凭手感写哈希）。

## §8 交付与验收接口（这就是你和 QA 窗的分工）

- QA 窗只做三件事：**复算你的读数**、裁"**执行与证据是否一致**"、开任务单。它不开发、不替你裁判据、不花钱。
- **每轮你交付两件事**：(a) 给总控**短回执**（≤10 行）；(b) 在 `backend/reports/w8/{DELIVERY.md,RELAY.md}` 留下**可复算的四件**：`文件:行号` ＋ **命令形状（含 cwd 与解释器）** ＋ **HEAD／镜像** ＋ **读数时刻**。
- **报数固定五件**：**数 ＋ 面 ＋ 谓词 ＋ 分母 ＋ 粒度**（run vs thread）。少了任何一件，QA 会退回——不是刁难，是因为本项目"两跑矛盾"全部出在这五件上。
- 三态读数：**达成／未达成／`n/a`**，外加 **`UNVERIFIED`**（没跑就写 `UNVERIFIED`，绝不写 0）。`0` 要先问"**这一族本来会不会非 0**"；无样本记 `n/a` 不记 0；空作用域记 `NULL`；**"未查"本身也是待测量**。
- ⚠️ 特别提醒（本项目 QA 与别窗互相逮到过两次的形状）：**你加了列 ≠ 你没动判据**。`red_total = assertion_failures + environment_errors` 一旦进了 `"PASS" if red == 0`，判定驱动量**已经变了**，此时写"谓词一字未动"会被 `git diff` 当场推翻。
