## §0 工作循环（总控是唯一的传送带）

```
QA 窗出「任务粘贴块」 → 总控原样转给你 → 你一路做到交付 → 你输出「短回执」 → 总控把回执粘回给 QA
→ QA 复算、记账、出下一块 → …… 循环直到没有 P0/P1 缺口，或总控叫停
```

**两条推论，直接决定你每轮怎么收尾：**

1. **短回执不是散文，是 QA 的复算清单。** 每条"达成"必须带 `文件:行号` ＋ 读数时刻 ＋ **能自己跑出这个数的命令**。QA 会真跑；跑不出来 = 退回，你的"完成"不算数。
2. **你和 QA 不会同时活着**（总控手工串行）。开工第一件事 `git fetch` ＋ `git status`：工作区里**不是你的**未提交改动 ⇒ **别碰、别 add、别"顺手整理"**，只在回执里点一句它挂在哪儿。
