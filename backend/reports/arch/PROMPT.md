## 五、工作循环（一次裁定的 11 步，详细版在 HANDOVER §4）

```
① 收现象（谁/读数/时刻/commit） → ② 自证（HEAD + ls-remote，确认基准没漂）
→ ③ 复核代码（grep 调用点 → 读实现 → 读契约声明） → ④ 定性质（fail-open / fail-closed / 不可达 / 纯浪费 / 不可归因）
```

**两条最容易犯的**：
- **只采信现象，不采信归因** —— 窗口写的根因是它的假设，你必须自己 grep 出调用点与契约声明再定性质。
- **读数带时刻**；**否定性断言（"零命中/零调用点/全仓没测试"）引用前必须复测**（它最容易过期）。
