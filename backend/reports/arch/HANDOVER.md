## 0. 三十秒版

- **你的产出不是观点，是"归属 + 判据"**：谁改、改哪个文件/键/行、改完怎么验。

### 3.3 读输入的纪律

- **只采信"现象"，不采信"归因"**。窗口写的根因是**它的假设**；你要自己 `grep` 出调用点、读实现、读契约声明，再定性质。

## 4. 一次裁定的完整工作循环（11 步）

```
① 收现象   谁报的 / 什么读数 / 什么时刻 / 哪个 commit
② 自证     git rev-parse HEAD + git ls-remote origin main   ← 确认基准有没有漂
③ 复核     grep 调用点 → 读实现 → 读契约声明（形状/默认值/是否显式声明）
④ 定性质   fail-closed? fail-open? 效率? 可观测性?          ← 决定级别
⑤ 拆号     一稿一事；"同机制 ≠ 同缺陷"（判据 = 触发面 + 修复面同源）
⑥ 取号     §6：双向 grep（代码 + commit message）
⑦ 定归属   §2 归属表 → 文件/键/行 + 判据（可机械复核的断言）
⑧ 落笔     外置脚本，同时改 07 与 RELAY（§7）
⑨ 回填     07 §4.8 登记行 + 版本/日期/修订表行 + RELAY 头"下一可用号"
⑩ 自检     grep 复核；脚本断言全过；无残留旧号
⑪ 记忆     MEMORY.md（易变层 ≤3000 字）/ REFERENCE.md（慢变全集）/ daily log
```

**④"定性质"的判据（用它的字面后果判，不用严重性形容词）**：

| 性质 | 后果 | 级别倾向 |
|---|---|---|
| **fail-open** | 该拦的没拦（口径失真 / 守卫静默失效 / 越权） | 🔴 P0 |
| **fail-closed** | 该过的没过（全拒） | 🔴 P0（会掩盖其他缺陷）或 P1 |
| **不可达** | 判据在生产永远拿不到输入 | 🔴 P0（等于该层没干活） |
| **纯浪费** | 正确性不受影响、只是白花钱 | ⚠️ P1 |
| **不可归因** | 出问题时没有外部证据 | P1 |

> 实例：`U-121` 的 7 个子事实里，**3 条是 fail-open**（口径谓词不注入 / 版本守卫永不触发 / 请求级 `max_rows` 静默失效）—— 这才是它值 P0 的原因，而不是"闸门红了"。

**每节必备四要素**：`事实（文件:行）` → `判据（可复核断言）` → `归属（谁改哪）` → `禁止动作`。

### 6.1 三条规则（原文见 `07 §4.8`）

- **① 登记表是唯一权威** —— "我看到的最后一个号 +1"**不是依据**（`U-38~U-40` 撞车已实证）。

- **③ 代价是下游窗口拿到的编号会失真** —— 各窗口 PROMPT 把"U-88~U-103 已用尽"当事实传递，一旦失真，下游整批引用全错。

**本表是"滞后真相"**：先查本表，再查 `reports/*/RELAY.md`，两者不一致时**以实现事实为准并回填本表**。

### 6.2 取号动作（**2026-09-21 新增，本项目已撞车 3 次**）

```bash
cd CommerceQL
N=U-122                      # 你打算用的号
git grep -n "$N" -- .        # ① 代码与已跟踪文件
git log --all --grep="$N" --oneline   # ② commit message
```

**两条都必须空**，才可以用这个号。**只查 §4.8 表是不够的** —— 表由人回填 ⇒ **必然滞后于代码**。三次撞车的成因都是这个：

### 6.3 一号一事的边界

- **一个号只允许一件事**。合并两个号的判据 = "**触发面 + 修复面同源**"，**不是**"底层机制相同"（`U-110` 的"并入"因此被撤销，而那是架构自己犯的）。
- 同一缺陷被**两个窗口以不同措辞各自提出** ⇒ 归属与修法可**一次裁定**，但判据的精确度要**逐家核**。
- **号一旦写进已发布文档就不能换义**（在途引用会静默错指）；撞车时**只改撞车的那一个号**，没被占用的邻号**不要顺手作废**（作废两个号 ≠ 更安全）。

## 7. 落笔工程：怎么改这两份大文档而不改坏

`docs/` **不在 git 里**（无 VCS 兜底），`07` 现在约 **3,526 行 / 527 KB**（2026-09-28 实测 `wc -l -c`；旧表述「35k 行」错了一个数量级）。所以：

### 7.1 硬纪律（每条都有血案）

| # | 纪律 | 血案 |
|---|---|---|
| 1 | **一次性改大文档 = 外置脚本**，不许手改长文 | `Edit` 在超长行上匹配失败率高 |
| 2 | **每个锚点恰好命中 1 次**（`count(anchor) == 1`），否则**中止不写盘** | `D4-evid` 因**凭记忆转述锚点**而 0 命中，脚本按设计中止 ⇒ 其余 17 处保持有效 ❤️ |
| 3 | **锚点必须从文件读原文**，不许凭记忆/凭摘要转述 | 同上 |
| 4 | **写盘前 `.bak`** | 上一轮 v5 的误改就是靠 `.bak` 回滚的 |
| 5 | **粗体奇偶守恒**：改前/改后同一行的 `**` 计数奇偶必须相同（**先剥掉行内 `` `…` `` 再数**） | `app/core/**` 里的 `**` 会造成**假阳**；`SEC21` 就因为一处"这条接缝**没有任何测试**"而整体失衡、被断言拦下 |
| 6 | **"Edit/脚本报成功" ≠ "文本已变"** | 见 7.3 事故 |
| 7 | **别嵌套粗体** `**a **b** c**` | 会让后续所有奇偶判断失效 |
| 8 | **先探测 EOL 再切行**（`docs/07` 与 `RELAY.md` 实测**全是 CRLF**）：读入 → 归一成 `\n` 运算 → 写盘按原 EOL 还原 → 回读比对 | v1.6.5 首跑：按 `"\n"` 切分后每行尾部留 `\r` ⇒ **所有 `endswith(" \|")` 锚点判断全灭**（脚本按设计中止、未写盘，但白跑一轮） |
| 9 | **裁定正文外置成数据文件**（`@@KEY` + 单行/块），Python 里只留锚点与断言 | v1.6.5：正文里的 ASCII 引号撞上字符串定界符 ⇒ `SyntaxError: unterminated string literal`；改外置后**这一类 bug 整类消失** |
| 10 | **回读断言要数竖线**：新插入的表格行，其 `\|` 计数必须 == 同表既有行 | v1.6.5：`U-122` 行漏了**收尾竖线** ⇒ 3 格 ≠ 同表 4 格，而"回读 == 内存产物"**照样通过** ⇒ **"文本已变"不等于"结构正确"**（该错由本轮自检抓出、当场补齐） |

## 11. 教训：架构窗口最容易犯的五类错（**每一类都犯过**）

### 11.1 编号：只查表、不查代码 ⇒ 撞车（**2026-09-21 刚犯**）

v1.6.4 第一稿把"闸门判据在生产不可达"记作 `U-118`，而 **W4 的 `8202204`（2026-09-21 18:18:56，已在远端 `main`）message 里已写 `U-118①`**。
**成因**：`07 §4.8` 当时写"下一可用 = `U-118`" —— **表滞后于代码**（W4 取号后未回填）。

**纪律**：§6.2 的双向 grep。这是同一条规则**第三次**被抓到。

### 11.2 把"分数不可用"读成"判定不可用"

v1.6.3 我预测 `bind` 会**转澄清**；实测 `binding_layer{L3}=3 / L4=0` ⇒ `decide()` 走 L3 就出结果、**根本没进 L4**。
⇒ **"分数不可用 ≠ 判定不可用"**。教训：**先读读数再写预测**，不要把"我以为它需要 X"当成"它没有 X 就不能工作"。

### 11.3 契约类断言写成不等式 ⇒ 文档无法机械同步

⇒ **判据要么给值、要么给"与某常量具名同源"**。另：契约测试要分清**钉键集**还是**钉值**。
