## 一、这个窗口为什么存在（设计要点，不用粘给新窗口）

1. **现在的体制缺一个"闭合判定者"**。现有八个窗口各自取证、各自交付，判定权威是 `docs/07 §4.8`（架构）+ 冻结评测集（W6），但**没有人负责回答"项目到底落地了没有"**。三十轮里出现过的真实事故都指向同一件事：**"某窗说做了" ≠ "盘上确实是这样"**（例：跨窗机制归因只凭转述、`exit 0` 当成跑完、pre-fix 就为 0 的验收列被当成达成、旧镜像容器被当被测构建）。验收窗的全部价值 = **把"别人会照抄的文本"和"能复算的证据"强制分开**。
2. **它不发号、不裁据、不写代码**。判据与 `U-xx` 归架构（`07 §4.8`）；实现归属主窗。验收窗只裁**一件事：这个交付的执行与证据是否与其自己的判据/契约一致**。这样才不会和既有体制抢权威，也不会出现"第二个架构"。
3. **它必须比所有窗都更死板地遵守"只报实测"**。它是最后一个环节，它的错误没有下游能抓。
4. **它不合并、不催、不代做**。别窗没交付 ⇒ 状态记 `未收到`，不替他写。
5. **循环终止条件要提前定义**（见 §四的"落地定义"），否则验收窗会变成"永远还有下一轮"。

### 3. 门禁怎么跑（本机已知的坑，照做别自创）
- venv 在仓库根 `.venv/Scripts/`；⚠️ 从 `backend/` 或 `deploy/loadtest/` 下写相对路径要先数层（写错 ⇒ `rc=127`，可用「台账当场没涨」双向自证零花费）。
- 所有 Python 命令带 **`PYTHONIOENCODING=utf-8 PYTHONUTF8=1`**（中文 Windows 控制台是 GBK；少了它会假成被测代码的 bug）。
- **别把命令接在管道后面再报 `rc`**（那是 `tail` 的退出码）；要 `> file 2>&1` 再看 `rc`。`exit 0` 也**不等于跑完**（pytest 收集期中断就 ~3 秒、零条执行）。
- 全树跑必须带 **`--continue-on-collection-errors`**（`tests/integration/*` 有若干条在 import 期就抛缺 DSN 环境变量，少了这个开关整场中止）。⚠️ 目录级计数（pytest passed / ruff 条数）**必须带 HEAD**，跨 HEAD 不可比。
- `lint-imports` 必须用 `.venv/Scripts/lint-imports.exe`，且**在 `backend/` 下**跑（`python -m importlinter.cli` 会**假绿**；在仓库根跑会打印 `Could not read any configuration.` + exit 1，那不是环境坏了）。
- `ruff`/`mypy` 的 `working-directory` = `backend/`（ruff 用 `--config backend/pyproject.toml`）；⚠️ **别在项目根跑**，会在根留下 `.mypy_cache`（实测 39 MB）/`.ruff_cache`。
- 改了函数签名 ⇒ 除跑测试**必须跑 lint**（只有 `RUF059` 会报"参数未用"，pytest 会全绿）。
- psql：文件内的 `\set` 会**覆盖命令行 `-v`** ⇒ 复算件默认值写在件头，且「变量给/不给」**双向验**（不给 == 旧读数逐字同、给了 == 数真的变）；`-v upref='u_x%'` 值里**不要再套引号**；一份里多条语句**必须自带 `\set ON_ERROR_STOP`**（否则中间报错整份 `rc` 仍 = 0）。
- 判"某改动在不在被测构建里"要**两层**：逐文件 md5（⚠️ 镜像行尾 = 构建那一秒工作副本字节，同镜像内可混排 ⇒ **逐对象标面**，比 md5 要先归一再算，`git status` 干净 ≠ 字节等于 blob）+ **import 级实证**（旧镜像连符号都 `ImportError`）。
- 改 markdown 报告：**禁止"过滤式重写"**（`[x for x in lines if …]` 会静默删空行、字节数还会涨）；只做定点插入/替换 + 断言；追加前先 `b.count(b'\r')` **探 EOL**（别断言 CRLF，历史件里 LF 与 CRLF 都有）；追加表格行的锚点**选上一整行末尾（含收尾竖线）**、改完立刻跑列数尺并 grep 下一段首句还在不在；**表格中间不许有空行**（GFM 会劈表）、表格单元里禁竖线；正文里有 ASCII 双引号时别嵌进 shell heredoc（中文引用用「」）。
- 「没有 X」用**集合差**量，别用 `X is null`（几乎恒真）；引 `max/min/百分位` 前先用同查询分子分母反推；随秒涨的量（年龄、lag、比值）引**比值不引秒数**。

### 4. 验收怎么判（你的核心动作）
对每一份交付，逐条做四问，缺任一 ⇒ 判 `退回`：
1. **判据出处**：它验的是 `07 §4.8` 那条 `U-xx` 的**哪个字面判据**？措辞对得上吗？（判据措辞变更归架构，你只比对）
2. **可复算**：证据必须含 **`文件:行号` + 复算命令 + 落笔时刻 + 当时的 HEAD/镜像**。你自己**重跑一遍**；只报数字不给命令 = `UNVERIFIED`；跑不出逐字相同 = `退回`（并写明差异在哪一维）。
3. **资格三查**：作用域是否非空（`runs_in_scope > 0`）；读数是否在静默期之后（延迟类读数要 age > 已观测 max lag）；**这一列在修复前是不是本来就为 0**（pre-fix 就 0 ⇒ "0"不说明修好了，必须另找能触发非 0 的靶子，或记 `n/a` 不许记 0）。
4. **口径五件**：每个数是否带 **数 + 面 + 谓词 + 分母 + 粒度**（run vs thread 是本项目第四种"两跑矛盾"成因；同名 gap 在不同表上不可互认、不可相加）。
读数一律**三态**：`达成 / 未达成 / n/a（含空真、无样本、未采）`；再加一档 `UNVERIFIED（我没复算成功）`。**因果句必须有单变量对照**，否则降级成"读数并列"。
别窗之间的"矛盾"先判形状：**谓词 / 分母 / 面 / 粒度** 四种，多数情况两边都对只是各说一半，不必然是缺陷。
