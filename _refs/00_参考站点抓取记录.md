## 3. 已抓取的关键事实清单（可直接引用）

### 3.1 Spider 1.0（官方站点）
- 10,181 问 / **5,693 条唯一复杂 SQL** / 200 库 / **138 领域** / 平均 5.1 表
- train 8,659（146 库）/ dev 1,034（**20 个未见过库**）
- 许可：**CC BY-SA 4.0**
- **2024-02-05 起停止接收提交、冻结榜单**；测试集已公开
- 榜单：MiniSeek **91.2** / DAIL-SQL+GPT-4+自洽 **86.6** / DPG-SQL+GPT-4+自校正 85.6 / DIN-SQL+GPT-4 85.3
- 官方指标：**Test Suite Accuracy**（自 2020-11-15 起），取代精确匹配

### 3.2 Spider 2.0（官方站点）
- **632 个真实企业工作流问题**；库常 >1000 列、环境 >3000 列
- **o1-preview 17.1% / GPT-4o 10.1%**（对比 Spider 1.0 的 86.6%）
- **不提供预定义 schema，需自动交互式探索数据库**
- 官方要求：**最终输出是 CSV 文件，而不是 SQL**
- 官��不推荐用 Gold SQL 做 SFT（影响评测公平）
- 三种设定：Snow（547，免费）/ DBT（68，DuckDB）/ Lite（547，含 SQLite 135）

### 3.3 ⭐ CoSQL（对本项目最有方法论价值）
- 对话版 Text2SQL，EMNLP'19
- **30k+ 轮对话 + 10k+ SQL**，3k 组 Wizard-of-Oz 对话，200 库 / 138 领域
- **官方原话**：每段对话模拟真实场景，用户探索数据库，SQL 专家"**用 SQL 取回答案、澄清歧义问题，或告知无法回答**"
  → 三大行为与我们 PRD §6.9 的三档门禁**完全同构**

### 3.4 SParC（ACL'19）
- Spider 的多轮/上下文版本
- **4,298 组连贯问题序列**（12k+ 单问），14 名 Yale 学生标注
- 200 库 / 138 领域，强调跨域泛化

### 3.5 ⭐ CSpider（中文，EMNLP'19，Westlake NLP）
- 与 Spider 同规模：10,181 / 5,693 / 200 库 / 138 领域，CC BY-SA 4.0
- **榜首 test 精确匹配仅 62.1**（华为 FastRAT+AST Ranking+GPT-4）
- 对比英文 Spider 榜首 91.2 → **中文低约 29 个点**
- **官方列出的中文额外挑战**：
  1. **表的表名/列名通常用英文表示**，增加了 question-to-DB mapping 难度
  2. **中文分词可能出错**，而列/单元格的语义单元可能是"词"
  3. **零代词（zero-pronoun）** 现象
- 2024-03-01 测试集公开、提交关闭

### 3.6 test-suite-sql-eval（官方指标实现）
- 针对每条金标准 SQL 自动生成**邻居查询 + 随机数据库**，在变体上执行比对语义等价
- README 原话：只报精确字符串匹配"**要么高估、要么低估真实语义准确率**"
- 参数：`--plug_value`（不预测值时的降级模式）、`--keep_distinct`、`--etype exec|match|all`

### 3.7 Spider hardness 规则
- 源码位置：`evaluation.py` 第 53-56、303-354、362-377 行
- 三级计数：Component1（WHERE/GROUP BY/ORDER BY/LIMIT/JOIN/OR/LIKE）、Component2（EXCEPT/UNION/INTERSECT）、Others（多聚合/多SELECT列/多WHERE条件/多GROUP BY列）
- 判定规则见 PRD §13.2
- **官方四级示例图见 `_refs/spider_examples.png`**

### 3.8 DeepSeek API（官方文档）
- 模型 ID：**仅 `deepseek-flash`（V4.1-Flash）与 `deepseek-v4-pro`（V4-Pro-0813）**；`deepseek-chat` / `deepseek-reasoner` 已退役
- base_url：`https://api.deepseek.com`（OpenAI 兼容）/ `/anthropic`（Anthropic 兼容）
- 上下文 1M，最大输出 384K，默认开启思考模式，支持 JSON Output 与 Tool Calls
- **限流 = 并发连接数**（flash 2500 / v4-pro 500，账号级），超限 429；扩容免费
- `user_id` 参数：内容安全隔离 + KVCache 隔离 + 调度隔离
- 价格（每 1M token，高峰/非高峰）：
  - flash：输入命中 $0.006/$0.003，未命中 $0.30/$0.15，输出 $1.20/$0.60
  - v4-pro：输入命中 $0.044/$0.022，未命中 $1.32/$0.66，输出 $3.96/$1.98
- **高峰 = UTC 01:00–04:00 与 06:00–10:00 工作日 = 北京时间工作日 09:00–12:00 + 14:00–18:00**

## 5. 本次抓取踩到的坑（供后续复用）

| # | 坑 | 解法 |
|---|---|---|
| 1 | **WebFetch 对 `yale-lily.github.io` 持续 fetch failed** | 改用 `curl` |
| 2 | **沙箱内外的 `/tmp` 不是同一个文件系统** | 沙箱外写的文件，沙箱内的命令读不到 → 统一在沙箱外完成读写 |
| 3 | **curl `-o` 写含中文的 MSYS 路径失败**（`curl: (23) client returned ERROR on write`） | 改用 **Windows 路径格式**（`E:/01_实训/...` 而非 `/e/01_实训/...`） |
| 4 | **bsk 在沙箱内必然挂死** | 所有 bsk 命令必须 `dangerouslyDisableSandbox` |
| 5 | **bsk 守护进程会被命令进程树回收**，导致 `status` 等命令挂死 | 用 `bsk daemon start --foreground` **挂在后台任务上**，使其跨命令存活 |
| 6 | **`bsk update` 可能只下不换** | 检查 `~/.local/bin/bsk.exe.update-*`；若存在说明替换失败（旧 exe 被占用），手动 `mv` 覆盖 |
| 7 | `bsk --version` 显示旧版本，但 `status` 里 `daemon_version` 是新版本 | 两者来自不同来源；**以 `bsk --version` 和 daemon.json 为准** |
